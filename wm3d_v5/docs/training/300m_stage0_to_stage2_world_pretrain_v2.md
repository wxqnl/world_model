# 300M Stage0-to-Stage2 World Pretraining v2

Goal: keep the 300M proof focused on VGGT-native 3D world dynamics first, then add a lightweight Hunyuan bridge and action scaffold. Hunyuan is treated as a pretrained renderer/control target, not the base world latent source. Text/description-only generation is optional Run G work and is not a blocker for Run1-3.

Tech stack: PyTorch DDP, 2 nodes x 8 H100, OXE+DROID cache, VGGT pooled tokens/depth, RGB cache, Qwen task embeddings, Hunyuan latent adapter.

## Revised Stages

### P0: Preflight

Keep the existing data, parameter, memory, and shape checks before any multi-node run. This stage should verify manifest/cache coverage, task embeddings, action stats, RGB/depth targets, VGGT token shapes, and checkpoint resume paths. It should not launch long GPU training.

### Run1 / Stage0: Visual/Depth Foundation

Purpose: first make the VGGT-native state usable as a high-quality visual/geometric world state. Stage0 concentrates on `context + action -> future tokens/depth/rough RGB`, with RGB/depth losses emphasized and unrelated generative/video/action-scaffold objectives disabled. This is the stage that must produce acceptable RGB/depth GIFs before scaling is meaningful.

### Run3: Benchmark Adaptation

Purpose: LIBERO/CALVIN/SimplerEnv adaptation after the world core and action scaffold are stable. Train local residual, waypoint, object-state, plan, and evaluator components while keeping the world core mostly fixed. Do not use this stage to repair base dynamics.

### Stage3: Generation (Hunyuan DiT-control, text->video)

Promoted from the former "Run G optional" note into a first-class, parameterized stage. A FROZEN world model supplies geometry / motion / layout control; a pretrained Hunyuan-Video T2V model supplies appearance and video realism through its native text encoders. Only a zero-init DiT control adapter is trained (world model + Hunyuan VAE/DiT/text-encoders all frozen), with a rectified-flow velocity objective (`noise - data`, embedded-CFG).

Launcher (parameterized — point `WM_CFG`/`WM_CKPT` at any trained world checkpoint):

```bash
WM_CFG=/data/Minko/world_model/wm3d_v3/configs/v3_p64_300m_stage2_oxe_droid20k_joint_visual_proposer_from_stage1_2node_v1.yaml \
WM_CKPT=/data/Minko/world_model/wm3d_v3/results/wm3d_v3_p64_300m_stage2_oxe_droid20k_joint_visual_proposer_from_stage1_2node_v1/ckpt/best.pt \
OUT_DIR=/data/Minko/world_model/wm3d_v5/results/wm3d_stage3_generation_hunyuan_dit_control_v1 \
bash scripts/run_stage3_generation_hunyuan_dit_control_v1.sh
```

In the flow: the stage0->stage2 watcher (`scripts/watch_300m_stage0_to_stage2_flow_v2.sh`) optionally continues into Stage3 when launched with `RUN_STAGE3_GENERATION=1`, conditioning Stage3 on the Stage2 best/latest checkpoint. Gated off by default.

| Setting | Value |
| --- | ---: |
| trainable | DiT control adapter only (zero-init) |
| frozen | world model + Hunyuan VAE / DiT / text encoders |
| objective | rectified-flow velocity (`noise - data`), embedded-CFG guidance |
| text conditioning | per-sample `task_text` -> Hunyuan text encoders (`--load_task_text`, default on) |
| `flow_shift` / `embedded_cfg_scale` | 7.0 / 6.0 |

Required for real text conditioning: `OXEWindowDataset` now emits raw `task_text` strings when `data.load_task_text: true` (the DiT-control trainer sets this automatically via `--load_task_text`). Without it, training silently collapses to a single constant prompt and the text encoder learns nothing instruction-specific.

Re-pointing to native3d: set `WM_CFG`/`WM_CKPT` to a native3d stage checkpoint. The control adapter now consumes native3d geometry directly — `pred_tokens` / `depth` / rough `rgb` **plus** `point` (world points `[B,T,H,W,3]`) and `pose_geom` (camera pose `[B,T,9]`) via `use_point`/`use_pose` encoders (`point_proj` Conv3d, `pose_proj` Linear). Both are optional and gated on availability, so depth-only (v3) checkpoints stay fully backward-compatible; the geometry encoders feed the fused control features while the DiT-facing output projections remain zero-init (exact no-op at start of training).

Verified end-to-end on GPU (140m native3d WM -> Hunyuan T2V DiT-control): both the depth-only and the native3d-conditioned (`point`+`pose_geom`) paths train a real rectified-flow velocity loss and checkpoint cleanly (`load_missing/load_skipped = 0`). Two prerequisites are baked into the launcher/trainer and must not regress: (1) `run_v5_generation_stage_hunyuan_dit_control_v1.sh` exports `PYTHONPATH=$V5_ROOT` so `wm3d_v3` resolves to the v5 tree (the editable install otherwise points at the depth-only `/data/Minko/world_model/wm3d_v3` tree, which lacks the adapter); (2) the trainer wraps the adapter forward + loss in `torch.enable_grad()` because loading the Hunyuan sampler globally calls `torch.set_grad_enabled(False)`.

Known minor gap: training samples the flow-matching sigma as `U(0,1)` without applying `flow_shift` to the train-time density, while inference shifts (`shift=7`). Velocity target is correct; consider logit-normal / shifted sigma sampling for train/infer parity.

Naming: this Stage3 is the **generation** capability stage. The separate "Run3: Benchmark Adaptation" above is downstream VLA/benchmark work, not part of the world-model + generation pretraining ladder.

Alternative in-model path: `configs/v3_p64_300m_runG_optional_text_world_prior_hunyuan_from_stage1_2node_v1.yaml` trains the in-model `world_prior` generator (text -> VGGT tokens) with CFG dropout + prior-Hunyuan loss inside the main trainer. The DiT-control launcher above is the preferred Stage3 (real Hunyuan T2V); the `world_prior` config remains the token-space generative alternative.

## Automatic Flow

Default Stage0->Stage1->Stage1.5->Stage2 watcher:

```bash
scripts/run_300m_stage0_visual_geom_oxe_droid20k_balanced_2node_v1.sh
nohup bash scripts/watch_300m_stage0_to_stage2_flow_v2.sh \
  > /data/Minko/logs/watch_300m_stage0_to_stage2_flow_v2.nohup.log 2>&1 &
```

The watcher runs Stage0, Stage1, Run1.5 Hunyuan Bridge, then Stage2. Stage2 resumes from the Run1.5 best/latest checkpoint. The watcher still runs RGB/depth and native3D evals after each stage. Generation canaries are skipped by default with `RUN_GENERATION_CANARY=0`; set `RUN_GENERATION_CANARY=1` only for optional Run G-style diagnostics. Stage3 text->video generation is likewise gated off; set `RUN_STAGE3_GENERATION=1` to continue into Stage3 after Stage2, or run `scripts/run_stage3_generation_hunyuan_dit_control_v1.sh` standalone.

## Success Checks

Run1/Stage0/Stage1 should show:

- Stable token/state, depth, RGB, and motion losses.
- Stage0 `drop_*` values at zero and no Hunyuan/prior losses.
- Stage0 RGB/depth metrics improving quickly enough to beat the failed `140m_stage0_core3d` probe.
- Stage1 optimizer logs showing `context_pixel` and `geom` in a 0.05x LR group.
- Native3D real-action-vs-counterfactual depth and depth-change wins remain strong.

Run1.5 should show:

- Trainable parameter log dominated by `context_pixel` plus the Hunyuan adapter.
- Hunyuan latent metrics improving without changing the world trunk.
- No prior-Hunyuan metrics driving total loss.

Run2 should show:

- Progress/proposer losses active and stable; evaluator/direct-policy losses are not expected in the current configs.
- World-prior and Hunyuan losses at zero/off.
- Frozen world trunk behavior in the trainer log via `trainable_prefixes`.
