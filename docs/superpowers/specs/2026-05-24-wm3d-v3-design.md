# wm3d v3 — Joint End-to-End World Model + VLA Spec

**Date:** 2026-05-24
**Builds on:** v1 (frozen-pipeline DualStream + IDM) and v2 (PixelDecoder + Cosmos zero-shot).
**Status:** Frozen design, in execution.

## 0. Why v3

v2 demos exposed the **domain-gap failure mode** of the pipeline-style design:
- Cosmos-Transfer1 trained on real-world video; LIBERO is sim → output looks like kitchen, not LIBERO
- Predicted depth and Cosmos's expected depth format don't align → blurry, "veiled" outputs
- Past/future depth discontinuity at frame 16/17 boundary → temporal incoherence
- No gradient between modules → can't co-adapt

v3 fixes all of this with **joint training on real-world data**:
- Switch data from LIBERO (sim) to **Open-X-Embodiment**: bridge + fractal20220817 + taco/jaco play (real WidowX, Everyday Robots, Franka, Jaco)
- Train everything end-to-end through Cosmos via LoRA: gradients flow VGGT-tokens → DualStream → depth → Cosmos → RGB
- Scale trainable params to **~400 M** (per user spec)
- Single integrated world model that ships as ONE forward call

## 1. Goals

1. **One model, one forward pass.** RGB+task in → predicted future RGB video + 7-DoF action chunk out, with shared latent and gradient flow.
2. **Real-world data.** Train on OXE subset (bridge + fractal + taco + jaco). LIBERO retained only as held-out cross-embodiment OOD probe.
3. **Native 3D.** Geometry decoder (depth/point/cam) trained alongside; serves as Cosmos depth control AND as direct geometric supervision.
4. **VLA.** Action chunk output via IDM + ActionProjHead, end-to-end trained with action labels.
5. **Demonstrable RGB.** Cosmos+LoRA produces RGB videos in the target domain (real WidowX / Franka), not sim aesthetics.

## 2. Non-goals

- Full Cosmos pre-training from scratch (we use frozen base + LoRA only).
- Multi-view stereo / NeRF / Gaussian splat output (depth + point map are enough).
- LIBERO closed-loop BC (deferred to v3.1; sim env install was blocker for v1).

## 3. Constraints

- 4 × H100 80 GB (GPUs 0-3 only).
- Cosmos-Transfer1-7B base + depth_control already downloaded.
- VGGT-1B, Qwen3-VL-Embedding-2B already in `/home/user01/Minko/models/`.

## 6. Training

### 6.1 Loss

```
L_total =     L_token              # tokens predicted ≈ real VGGT(future)
          + 0.2 · L_depth          # geom L1 + Chamfer + pose L2
          + 0.3 · L_rgb            # LPIPS + L1 against real future RGB,
                                    #   via Cosmos+LoRA on predicted depth
          + 1.0 · L_action         # 6-D pose MSE + gripper BCE
          + 0.01 · L_idm_reg       # z_a norm reg
```

### 6.2 Compute strategy

- **bf16 autocast** throughout, fp32 master weights.
- **Pre-cache** all frozen-encoder outputs (VGGT tokens, Qwen embeddings, RGB, depth, Cosmos VAE latents).
- **Cosmos diffusion at training time**: load 7B base + LoRA in bf16 (~14 GB), enable **gradient checkpointing** on Cosmos blocks. LoRA adapters are the only trainable params on Cosmos.
- **DDP across 4 GPUs**; batch 4 per GPU (Cosmos forward dominates memory).
- **Gradient accumulation = 8** → effective batch 128.
- **Diffusion timestep sampling**: random t ∈ [0, T_train=1000] per step; train MSE on predicted noise.
- **LoRA** via `peft` library on all attention q/k/v/out projections in Cosmos diffusion U-Net.

### 6.3 Training schedule

- 80 epochs over ~30K episodes; epoch = 1 pass through all training windows (~1M windows at stride 4 / T=16 + k=8).
- AdamW lr 1.5e-4 → 1.5e-5 cosine, 2000-step warmup, weight decay 0.02.
- Estimated step time: ~2-3 s on 4×H100 with Cosmos in loop.
- ~1M steps × 2.5 s = ~700 hours wall → **infeasible**.

So we revise the schedule:
- **Stage 1 (warmup, no Cosmos): 20 epochs** — only L_token + L_depth + L_action. Fast (~0.5 s/step). Wall ~10 h.
- **Stage 2 (joint with Cosmos LoRA): 10 epochs** — add L_rgb. Slow (~3 s/step). Wall ~70 h ≈ 3 days.
- Total: **~3.5 days continuous compute on 4×H100**.

### 6.4 Sanity checks before full run

1. 1-episode overfit smoke (full forward + loss + backward).
2. 100-step DDP smoke (verify mem fits + loss decreases).
3. Stage 1 only on small subset first (verify training-time tokens/depth/action all converge).

## 9. Risks

| Risk | Mitigation |
|---|---|
| Cosmos LoRA training instability on 4 GPUs | Stage 1 first (no Cosmos); Stage 2 only after token/depth/action stable. Save ckpts every 2 epochs. |
| Memory OOM with Cosmos in loop | Gradient checkpointing, batch 4 per GPU + grad accum 8, bf16 throughout. |
| OXE tar reading is slow | Pre-extract pickles to disk (~98 GB) before caching. |
| Action format mismatch across datasets | `action_normalize.py` unifies to 7-D delta-xyz + delta-rpy + binary-gripper. |
| Cache disk space (500 GB) | Use int8/fp16, drop kuka dataset for now. |
| Cosmos config + checkpoint format mismatch | Test loading Cosmos with LoRA via PEFT before serious work; fallback: train LoRA only on depth ControlNet (smaller) if main diffusion is too hard. |

## 10. Acceptance criteria

- [ ] Single `JointWorldModel` class with one `forward()` taking RGB+text and returning predicted RGB+action.
- [ ] Trained on at least 20K real-world episodes from OXE.
- [ ] LoRA-adapted Cosmos produces RGB visibly closer to real WidowX/Franka domain than zero-shot.
- [ ] Action accuracy on held-out OXE episodes within reasonable range (gripper >85%, pose RMSE < 0.2).
- [ ] All four eval axes reported in REPORT_V3.md.
