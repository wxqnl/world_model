# wm3d v1 — Design Spec

**Date:** 2026-05-22
**Project:** Native-3D world model with scene generation + scene prediction + VLA, on frozen VGGT geometric tokens and frozen Qwen3-VL semantics
**Status:** Spec frozen, ready for implementation plan

---

## 0. One-paragraph summary

We build a 3D-native world model on **frozen VGGT-1B geometric tokens** + **frozen Qwen3-VL-Embedding-2B semantics**, with a single trainable **DualStreamDynamics** module (~165M including the auxiliary geometry decoder) whose two parallel transformer streams talk to each other through periodic cross-attention. The state stream predicts future tokens; the action stream is an inverse-dynamics module (IDM) that emits continuous latent action codes, which a small projection head decodes into 7-DoF robot actions. Geometry (depth / point map / camera) is read out by VGGT's own decoders. We train on **LIBERO** (locally available, 4 splits, ~1728 trajectories), with a manifest interface that allows trivial extension to Open-X-Embodiment later. Evaluation: token L2/cosine, geometry Chamfer-L1, IDM action accuracy, and **LIBERO closed-loop BC success rate** (40 tasks × 5 seeds × 50 episodes). This is the v1 of a project that will later add a token→RGB decoder and ControlNet→Cosmos for full video generation.

## 1. Goals and non-goals

**Goals (v1):**
1. Implement DualStreamDynamics: parallel state + action transformers with periodic bidirectional cross-attention.
2. Implement IDM with continuous latent action z_a + supervised z_a→a_real projection (hybrid IDM).
3. Train end-to-end on LIBERO with both VGGT tokens and Qwen3-VL embeddings frozen and pre-cached.
4. Evaluate on four axes: token prediction, geometric reconstruction, action accuracy, **closed-loop LIBERO BC**.
5. Design clean interface slots so v2 can drop in (a) a token→RGB decoder, (b) a ControlNet-style depth-conditioned video diffusion adapter, without touching v1 code.
6. Land a written report with all four metrics and the schedule/coupling choices documented.

**Non-goals (v1, explicitly):**
- ❌ RGB video generation. v1 outputs depth + point map for "scene generation" — Cosmos / SVD integration is v2.
- ❌ ControlNet adapter implementation. Interface slot is defined; body is empty.
- ❌ Web-scale / OXE / DROID training. Manifest format is OXE-compatible; v1 ships with LIBERO only.
- ❌ Action-free video pretraining. v1's IDM trains with action labels. The latent z_a can later be retrained without labels but that is a v2 experiment.
- ❌ Multi-embodiment generalization claims.

## 3. Architecture

### 3.1 Pipeline

```
[task text]──┐
             ├─► Qwen3-VL-Embedding-2B (frozen) ──► c ∈ R^2048
[frame_0] ───┘

[RGB frames T=16] ─► VGGT-1B (frozen) ─► s_{0..T-1} ∈ R^{T×64×2048}
                                          (pooled 8×8 tokens, bf16)

         ┌────────── DualStreamDynamics (~155M; +10M aux geom) ─────┐
         │                                                          │
   s ──► │   State stream  (~110M, ~12 transformer layers)          │
         │     ↕  cross-attn (bidirectional, layers 3/6/9/12)       │
   c ──► │   Action stream / IDM  (~40M, ~8 transformer layers)     │
         │                                                          │
         └──────────────────────────────────────────────────────────┘
                        │                              │
              ŝ_{T..T+k-1}  (predicted tokens)       z_a (k=8 latent actions)
                  k×64×2048                              k×128
                        │                              │
              ┌─────────┴─────────┐         ┌──────────┴──────────┐
              │ Geometry decoders │         │ ActionProjHead       │
              │ (see §3.5)        │         │ z_a → â ∈ R^{k×7}    │
              └───────────────────┘         └──────────────────────┘
                  depth/point/cam                 7-DoF action

  v1 interface slots (not implemented):
   ┌── PixelDecoder slot:  ŝ_{t} → RGB frame_{t}    (v2: token-DiT or SVD adapter)
   └── VideoAdapter slot:  depth_seq → ControlNet → Cosmos    (v2)
```

### 3.2 State stream

- **Input flatten.** `s ∈ R^{B×T×P×D}` with `T=16`, `P=64`, `D=2048` → flatten patch dim → `[B, T·P=1024, D]` token sequence.
- **Conditioning.** Concat one `c` token at the front (broadcast across batch), plus a learnable [START] token. Total 1026 tokens. Add separable (frame index, patch index, modality) positional embeddings.
- **Backbone.** 12 transformer layers, hidden 1024, 16 heads, GELU, pre-norm, flash-attention. Param count: ~110M with feedforward expansion ×4.
- **Decoder head.** A query-token bank of `k=8` learnable tokens cross-attends to the state stream output (2 layers of decoder cross-attn, hidden 1024). Then a linear `1024 → 64·2048 = 131072` outputs ŝ_{T..T+k-1} reshaped to `[B, k, 64, 2048]`.
- **No autoregression in v1.** All k future frames are emitted in one forward pass. This is the simplest decision; autoregressive decoding can be added in v2 if rollout quality is poor.

### 3.3 Action stream (IDM)

- **Same token shape** as state stream input; runs in parallel on the same s+c.
- **Backbone.** 8 transformer layers, hidden 768, 12 heads. Param count: ~40M.
- **Latent bottleneck.** A second query-token bank of `k=8` query tokens cross-attends to the action stream output, producing `z_a ∈ R^{k×128}`.
- **Regularization.** L2 penalty on z_a magnitude (β = 0.01) to prevent unbounded growth. We deliberately do NOT use VQ in v1; if z_a collapses or explodes in practice we revisit.
- **No image future input.** IDM in v1 sees only past observations (it's not given s_{T..T+k-1} as input). This is closer to "predict the action plan from context" than "infer action a_t from (s_t, s_{t+1})" — we trade off classical IDM semantics for the practical need of the action stream's z_a to be available during rollout (when future states are not known).

### 3.4 Cross-attention blocks

- **Placement.** After state-stream layer 3, 6, 9, 12.
- **Each block is bidirectional:** two `nn.MultiheadAttention` calls:
  1. `state_h ← state_h + xattn(query=state_h, key=action_h, value=action_h)`
  2. `action_h ← action_h + xattn(query=action_h, key=state_h, value=state_h)`
- **Shared dim** 1024 (action stream projects up to 1024 for cross-attn, back down to 768 internally).
- **Param count:** ~5M total across the 4 blocks.

### 3.5 Geometry decoders (for predicted tokens)

**The honest problem:** VGGT's real `depth_head` / `point_head` consume `(aggregated_tokens_list, images, ps_idx)` — they need the **full multi-layer aggregator output** (not pooled tokens) and the actual RGB. We have neither for future predicted frames.

**v1 resolution:**
1. **For input frames** (`t ≤ T-1`): we cache VGGT's actual depth + point + camera output for the cached input frames. This is ground truth for input-side geometry.
2. **For predicted frames** (`t ≥ T`): we train a small auxiliary `PooledTokenGeomDecoder` (~10M params, deeper than the prototype's 0.88M stand-in but still small) that maps pooled tokens `[64, 2048] → depth [64, 64]` + `point [64, 64, 3]`. It is trained on cached `(real_pooled_token, real_VGGT_depth_at_64×64)` pairs from the input-side cache. Then at eval we apply it to ŝ to get predicted depth/point.
3. **For camera pose**: we directly regress a 9-dim pose encoding (quat + translation + log-fov) from a small head on the same pooled tokens. Camera supervision comes from VGGT's `camera_head` output, cached during the input pass.

This is "VGGT geometry decoding light." A v2 upgrade is to also cache + predict the full aggregator output, which is a much bigger investment.

### 3.6 ActionProjHead

- `z_a [B, k, 128] → â [B, k, 7]`.
- 4-layer MLP, hidden 512, GELU, per-dim layer norm at output. Shared across the k chunk steps.
- Gripper dim (index 6) gets a separate sigmoid head for BCE; the 6 pose dims go through tanh-scaled output.
- ~1M params.

### 3.7 Param count

| Component | Params | Trainable? |
|---|---|---|
| VGGT-1B encoder + decoders | ~1.0 B | ❄️ frozen |
| Qwen3-VL-Embedding-2B | 2.0 B | ❄️ frozen |
| State stream | 110 M | 🔥 |
| Action stream (IDM) | 40 M | 🔥 |
| Cross-attn blocks ×4 | 5 M | 🔥 |
| ActionProjHead | 1 M | 🔥 |
| PooledTokenGeomDecoder | 10 M | 🔥 |
| **Total trainable** | **~166 M** | |

## 4. Data pipeline

### 4.1 Manifest format

JSONL, one record per clip:

```json
{
  "clip_id": "libero_spatial/ep_000000",
  "dataset": "libero",
  "split": "libero_spatial",
  "embodiment": "franka",
  "n_frames": 124,
  "fps": 20,
  "video_paths": {"main": ".../image/episode_000000.mp4",
                  "wrist": ".../wrist_image/episode_000000.mp4"},
  "data_parquet": ".../data/chunk-000/episode_000000.parquet",
  "task_text": "pick up the can and place it on the plate",
  "action_dim": 7,
  "action_kind": "delta_pose+gripper"
}
```

`wm3d/data/manifest.py` writes / reads this format. `wm3d/data/libero_loader.py` ingests the lerobot directories into manifest records. To add OXE later: write a new ingestor that emits the same record shape.

### 4.2 Pre-caching

Two cache types, both bf16, both stored under `/home/user01/Minko/datasets/cache/wm3d/`:

| Cache | Per-frame size | Total est. (4 splits) | Path |
|---|---|---|---|
| `vggt_pooled/{clip_id}.npy` — `[n_frames, 64, 2048]` bf16 | 256 KB | ~55 GB | `cache/wm3d/vggt_pooled/` |
| `vggt_geom/{clip_id}.npz` — `depth [n,64,64]`, `point [n,64,64,3]`, `pose [n,9]` bf16 | ~50 KB | ~10 GB | `cache/wm3d/vggt_geom/` |
| `qwen_taskemb/{clip_id}.npy` — `[2048]` bf16 (one per clip, fed `task_text + frame_0`) | 4 KB | ~10 MB | `cache/wm3d/qwen_taskemb/` |

**Why cache geometry too:** lets us train the `PooledTokenGeomDecoder` and run geometry eval without re-running VGGT decoder.

**Cache builders:** `scripts/cache_vggt.py`, `scripts/cache_qwen.py`. Both DDP-launchable on 4 GPUs.

### 4.3 Window dataset

`wm3d/data/window_dataset.py`:

- For each clip, sample windows of length `T+k = 24` (16 input frames + 8 future).
- Stride = 4 frames (so each clip yields ~25 windows on average).
- Return `dict(s_in [16,64,2048], s_tgt [8,64,2048], geom_tgt {...}, action_tgt [8,7], c [2048], clip_id)`.
- Train/val split: 90/10 by clip (not by window — no clip overlap).

## 5. Training

### 5.1 Losses

```
L_state    = MSE(ŝ_tgt, s_tgt) + λ_cos · (1 - cos(ŝ_tgt, s_tgt))
L_geom     = L1(depth_pred, depth_tgt) + chamfer_L1(point_pred, point_tgt)
             + L2(pose_pred, pose_tgt)
L_action   = MSE(â_pose, a_pose_tgt) + λ_grip · BCE(â_grip, a_grip_tgt)
L_idm_reg  = β · mean(z_a²)
L_total    = L_state + α_g · L_geom + α_a · L_action + L_idm_reg
```

Weights (initial): `λ_cos=0.1`, `λ_grip=0.5`, `α_g=0.2`, `α_a=1.0`, `β=0.01`.

### 5.2 Optimization

- **Optimizer:** AdamW, lr 3e-4, weight_decay 0.05, betas (0.9, 0.95).
- **Schedule:** 1000-step linear warmup → cosine decay to 3e-5.
- **Precision:** bf16 forward + fp32 master weights.
- **Distributed:** torch.distributed DDP across GPUs 0-3.
- **Batch size:** per-GPU 32 windows → 128 effective. Adjust down if OOM.
- **Gradient checkpointing:** off by default, enable if OOM.
- **Gradient clipping:** 1.0.
- **Epochs:** 60 epochs over all 4 splits combined (~1500 clips × ~25 windows ≈ 37K windows → ~290 batches/epoch → ~17K steps total).
- **Estimated wall:** 12-18 hours on 4× H100.

### 5.3 Logging

- TensorBoard. Logged: `L_state, L_geom, L_action, L_idm_reg, L_total`, per-component val every epoch, z_a norm distribution, learning rate, grad norm.
- Checkpoint every 2 epochs + best-val-L_total.

## 6. Evaluation

### 6.1 Held-out

10% of clips per split (~43 clips/split, ~170 total). Same evaluator code on each split → per-split table + overall.

### 6.2 Metrics

| # | Metric | What it tells us |
|---|---|---|
| 1 | val L_state (token MSE) + cos sim | Are predicted tokens close to real tokens? |
| 2 | val depth L1 (median-normalized) + point Chamfer-L1 (m) + pose L2 | Does "predicted token → geometry" reconstruct the real scene? |
| 3 | per-frame action L2, per-dim L2 (6 pose), gripper accuracy | Can the action projection head decode usable actions? |
| 4 | LIBERO closed-loop BC success rate, 40 tasks × 5 seeds × 50 ep | Is this thing a usable VLA? |

### 6.3 LIBERO closed-loop

- `wm3d/eval/libero_bc.py` boots the LIBERO simulator (uses `robosuite`, install via `pip install robosuite==1.4.0` + LIBERO's task suite).
- Policy: at each control step, take last 16 observations through VGGT+Qwen pipeline, run DualStream forward, read out â[0] (first action of the chunk), execute. Re-plan every 4 steps (action chunking with overlap).
- 40 tasks = 10 per split × 4 splits. 5 seeds × 50 episodes = 250 per task → 10K total rollouts.
- Estimated wall: ~24 hours on 4 GPUs (rollouts are cheap, sim is the bottleneck).
- Report mean ± 95% bootstrap CI per split and overall.

### 6.4 Sanity checks before the real eval

1. **Real-token replay**: feed real tokens through frozen pipeline, train ActionProjHead only on z_a from IDM — does it recover actions ≥ 90% accuracy on val? If not, IDM hasn't picked up action structure.
2. **Geometry decoder sanity**: train PooledTokenGeomDecoder for 10 epochs on real (pooled, depth) pairs and confirm L1 < 0.15 on real val (matches/exceeds Phase 2 prototype's 0.166).
3. **Single-clip overfit**: train full model on 1 clip for 100 steps, confirm all 4 losses go to ~zero. Signals plumbing is right.

## 8. Implementation phases

Each phase ends in a green test → smoke run → checkpointable artifact. Plan to span multiple sessions.

| Phase | Deliverable | Gate | Est. wall |

| **P1. Data + manifest** | LIBERO manifest builder; window dataset; unit tests pass | Manifest covers all 4 splits; window dataset returns correct shapes | 1 day |
| **P2. Caching** | VGGT + Qwen cache builders; all 4 splits cached on disk | Caches verified by hash + sample read | 1.5 days (mostly cache compute) |

## 9. Risks and how we'll handle them

| Risk | Likelihood | Mitigation |
|---|---|---|
| LIBERO simulator install (mujoco / robosuite / LIBERO benchmark version dance) | High | Get simulator working in P0/P1 against a smoke task. Time-box; if 2 days insufficient, drop P8/P9 closed-loop and document as v1.5 deliverable. |
| Qwen3-VL forward latency in cache builder | Low | 2B model, ~1500 clips. Worst case ~30 min total on 1 GPU. |
| VGGT real decoder requires aggregator output (not pooled) — addressed but a real limitation | Medium | Documented in §3.5. v1 ships with learned auxiliary decoder + cached real ground truth on inputs. Comparing predicted-decoder output vs real cached output is fair and reproducible. |
| IDM latent z_a collapse | Medium | Start with L2 reg β=0.01; monitor z_a norm/var; if collapse, switch to bottleneck dim 64 or add a VICReg-style regularizer. |
| Training instability with cross-attn at fp/bf16 | Medium | Pre-norm everywhere; gradient clipping 1.0; warmup 1000 steps. |
| 4-GPU OOM with batch 32 per GPU | Medium | Drop to 16 per GPU; gradient checkpointing if needed. |
| LIBERO simulator slow → 24 h estimate too low | High | Profile early; fall back to 20 tasks × 3 seeds × 25 ep if needed. Document scope reduction in report. |

## 10. Open questions intentionally deferred

These are real questions but **not blockers for v1**:

1. Should the action stream additionally see future state tokens during training (true classical IDM), with a teacher-forcing approach? (v1 = no; v2 candidate.)
2. Should we add a flow-matching probabilistic head on top of state stream for generative diversity? (v1 = deterministic; v2 candidate.)
3. Should the cross-attn blocks include time-shift / causal masking? (v1 = full visibility; revisit if rollouts drift.)
4. PixelDecoderSlot: train a small DiT vs adapt SVD vs adapt Cosmos? (v2 decision.)

## 11. Acceptance criteria for v1 (what "done" means)

A v1 release is "done" when:

- [ ] All four eval metrics reported on all four LIBERO splits.
- [ ] LIBERO closed-loop BC success rate is reported (even if low — a number with a CI is the deliverable).
- [ ] The full pipeline reproduces from a clean checkout in one `bash scripts/run_all.sh` (cache + train + eval), modulo data download.
- [ ] `REPORT_V1.md` exists, has tables, plots, interpretation, and an honest "what didn't work" section.
- [ ] PixelDecoderSlot + VideoAdapterSlot exist as Protocols with dummy implementations, so v2 can attach without surgery.
