# wm3d v2 — Design Spec Addendum

**Date:** 2026-05-23 (Builds on v1 spec `2026-05-22-wm3d-v1-design.md`)
**Status:** Frozen, ready for implementation

## 0. What v2 adds on top of v1

v1 shipped: DualStreamDynamics + IDM + auxiliary geometry decoder + offline metrics (token cos 0.998, depth L1 0.022, gripper acc 96.2%).

v2 fills in the bottom half of the original architecture image:

```
v1: [RGB] → VGGT → token → DualStream → ŝ → [aux depth decoder] → depth
v2:                                                                  ↓
                                                       ControlNet (= Cosmos-Transfer1)
                                                                  ↓
                                                          Cosmos (frozen) video diffusion
                                                                  ↓
                                                            RGB video output
```

Plus closes out v1's deferred items: LIBERO closed-loop BC + a small Token→RGB decoder (fast preview path that does not depend on Cosmos).

## 1. Goals

1. **End-to-end RGB video pipeline.** Input: T=16 LIBERO frames + task text. Output: k=8 future RGB frames generated by Cosmos-Transfer1 conditioned on our predicted depth.
2. **Token→RGB fallback.** A small (~10-30M) auxiliary decoder mapping pooled tokens → RGB; lets us produce comparison videos without depending on the Cosmos pipeline.
3. **LIBERO closed-loop BC.** The v1.5 deferral. Fresh conda env that satisfies all four deps. Run 40 tasks × 5 seeds × 50 ep.
4. **Higher-resolution geometry.** Add 224×224 depth cache (in addition to existing 64×64) so Cosmos-Transfer1 gets a real-quality depth signal. Train a small upsampler from 64×64 → 224×224 for the predicted depth.
5. **Final demo deliverable.** Side-by-side video showing: real input frames | real future frames (GT) | model-predicted depth | Cosmos-generated RGB | Token→RGB fallback.

## 2. Non-goals (still)

- Custom-from-scratch ControlNet for vanilla Cosmos. Cosmos-Transfer1 IS NVIDIA's ControlNet for Cosmos, already trained on depth+canny+edge controls. Re-training is not the user's bar (decision in 2026-05-23 chat).
- Multi-embodiment / OXE training. Manifest is OXE-compatible; v2 stays LIBERO-only.
- Real VGGT decoder on PREDICTED tokens. v1's aux depth decoder reaches L1=0.022 (7.5× tighter than Phase 2 prototype's stand-in). Caching full VGGT aggregator output for prediction is ~1 TB and the gain over the aux decoder is not justified. The aux decoder IS the "VGGT decoder slot" in our pipeline. v2 caches additional 224×224 depth from VGGT's real depth_head on INPUT frames as ground-truth for the upsampler + as direct input to Cosmos for past frames.

## 3. Constraints (unchanged from v1)

- 4 × H100 80 GB, GPUs 0-3 only.
- Cosmos-Transfer1 license: NVIDIA Open Model License (research, non-commercial). Need HF token + license acceptance.
- Cosmos-Transfer1-7B weights: ~24 GB on disk.

## 4. Architecture v2

```
[task text]──┐
             ├─► Qwen3-VL-Embedding-2B (frozen)  ──► c ∈ R^2048
[frame_0] ───┘

[RGB T=16] ─► VGGT-1B (frozen) ─► s_{0..15} ∈ R^{T×64×2048}

                              [v1 DualStreamDynamics, frozen at v1 best.pt]
                                        ↓                    ↓
                                ŝ_{16..23}                 z_a → action chunk (v1)
                                  ↓                                       ✅ v1
                       ┌──────────┼──────────┐
                       ▼          ▼          ▼
                v1 aux geom   token→RGB  v2 NEW: depth upsampler
                64×64 depth   decoder      64×64 → 224×224 depth
                              (~30M new)        (~5M new)
                                  ↓                ↓
                           RGB preview      v2 NEW: pad/resize → Cosmos input
                              (v2 NEW)             ↓
                                            Cosmos-Transfer1 7B (frozen)
                                            depth → RGB video
                                                    ↓
                                          generated future RGB
                                                    ✨ the image's bottom half
```

Three new trainable pieces (none modifies v1 DualStream):
- **PixelDecoder** (~30 M): `[B, k, 64, 2048] → [B, k, 3, 256, 256]`, small DiT-ish ConvTranspose stack. Trained on cached (pooled_token, RGB) pairs from input frames.
- **DepthUpsampler** (~5 M): `[B, k, 64, 64] → [B, k, 224, 224]`, learned bilinear-residual. Trained on cached (64×64 aux, 224×224 VGGT) depth pairs from input frames.
- **CosmosAdapter** (glue): no params, just data plumbing. Takes our predicted 224×224 depth + Cosmos's expected input format and returns RGB video.

## 5. New data caches

| Cache | Shape (per clip) | Size estimate (1693 clips) | Path |
|---|---|---|---|
| `vggt_depth_224/` `[n_frames, 224, 224]` fp16 | ~25 MB/clip | ~42 GB | `cache/wm3d/vggt_depth_224/` |
| `rgb_pairs/` `[n_frames, 3, 256, 256]` uint8 (decoded from mp4) | ~24 MB/clip | ~40 GB | `cache/wm3d/rgb_pairs/` |

Both built from existing LIBERO mp4 + VGGT inference. Reuses the cache pipeline pattern.

## 7. Risks

| Risk | Mitigation |
|---|---|
| Cosmos-Transfer1 needs CUDA / TRT version we don't have | Use the HF / vanilla PyTorch inference path, not Triton/TRT. NVIDIA ships both. |
| Cosmos license requires HF token acceptance | Have user run `huggingface-cli login` once + accept license on model page. |
| 224×224 depth from our predictor is too coarse for Cosmos visual quality | Cosmos-Transfer1 was trained on 720p+ depth. Our 224×224 upsampled is much coarser. Quality may suffer; document as "v2 demo scale, v3 trains the upsampler on higher-res VGGT-extracted depth." |
| LIBERO closed-loop BC env still has dep conflicts | Build fresh conda env from scratch with pinned versions matching robosuite 1.4.1 numpy <2 and a separate cached transformers path for Qwen calls. Document precise versions. |
| Cosmos inference is slow (multi-min per video) | Batch demo videos. Aim for ~20 demo clips, ~2 h total. |
